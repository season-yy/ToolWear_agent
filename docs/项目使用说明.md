# 刃知：完整使用说明

本文是“刃知：基于 AgentTeams 的刀具磨损监测算法辅助平台”的唯一完整使用指南。它说明项目由什么组成、每次如何启动、前端如何操作、Element 用来做什么，以及初赛需要提交哪些材料。

## 1. 先理解四个组成部分

| 部分 | 地址或位置 | 作用 |
| --- | --- | --- |
| Streamlit 前端 | `http://127.0.0.1:18101/` | 新建实验、选择模块、训练、诊断和查看证据 |
| FastAPI 后端 | `http://127.0.0.1:18100/` | 状态机、训练服务、Agent 工具和 Evidence API |
| AgentTeams + Element | `http://127.0.0.1:18088/` | 六 Agent 的官方协作运行时和 Matrix 会话界面 |
| SQLite 与运行目录 | `D:\AI_infra` | 保存实验状态、模型、图表、报告、日志和证据 |

前端不是后端，Element 也不是训练页面：

- **前端实验台**用于完整业务操作，是日常演示的主入口。
- **FastAPI**在后台接收页面和 Skill 请求，一般不直接操作。
- **Element**用于查看或发起 AgentTeams/Matrix 会话，证明多 Agent 确实在官方框架中协作。
- **SQLite**保存可恢复的业务状态和可检索记忆索引，不保存 PHM2010 原始信号本体。

## 2. P0 已实现范围

- 数据：PHM2010 C1，每个 cut 一个多通道 CSV。
- 信号：`force_x/force_y/force_z`、`vibration_x/vibration_y/vibration_z`、主轴电流。
- 标签：三刃 VB 默认取最大值，按 `90/130/160 um` 划分四阶段。
- 样本：4096 点窗口、50% 重叠、每个 cut 最多 32 个窗口。
- 切分：完整 cut 分组的 60% / 20% / 20%，禁止同一文件跨集合。
- 小样本：只在训练集内部按四阶段比例抽取 20%。
- 模型：RandomForest、ExtraTrees 和 CUDA 1D-CNN。
- 输出：Macro-F1、Balanced Accuracy、分类报告、混淆矩阵、validation-only t-SNE、结构化诊断、报告和 Evidence。

C4/C6 跨刀具、迁移学习、DANN、注意力、多分支融合和 VB 连续值回归属于后续路线，不在 P0 中宣称完成。

## 3. 第一次运行前

### 3.1 准备 Python

项目要求 Python `3.12`。在仓库根目录执行：

```powershell
python -m pip install -e ".[dev]"
```

本机已验证解释器为：

```text
F:\uploadtool\anaconda\envs\ToolWear_agent\python.exe
```

### 3.2 配置 `.env`

```powershell
Copy-Item .env.example .env
```

至少检查以下配置：

```dotenv
LLM_API_KEY=
LLM_MODEL=qwen3.7-flash-2026-07-15
AI_INFRA_ROOT=D:/AI_infra
PHM2010_RAW_ROOT=D:/AI_infra/datasets/raw/phm2010
DATASET_MANIFEST=D:/AI_infra/datasets/manifests/phm2010.yaml
TRAIN_DEVICE=cuda
```

可用备选模型已列在 `.env.example`。不要把真实 `.env`、Matrix 密码、Token 或 API Key 提交到 Git。

### 3.3 准备 PHM2010

本机原始数据来源是：

```text
D:\desk\TCM课题2025.10.13-11.13\现有数据集\PHM 2010
```

项目运行时通过数据集清单登记 C1 路径，处理后的清单、标签、窗口和切分缓存统一放在 `D:\AI_infra`。不要把原始数据复制进代码仓库。

## 4. 每次打开项目时怎么启动

### 4.1 启动 Docker Desktop

等待 Docker 引擎变为可用。只需要 ToolWear 对应的 AgentTeams 容器；其他 baseline 示例 Team 与本项目无关。

如果已有 ToolWear 容器只是停止，可执行：

```powershell
docker start agentteams-controller agentteams-manager
docker start agentteams-worker-toolwear-experiment-manager agentteams-worker-toolwear-data-steward agentteams-worker-toolwear-algorithm-architect agentteams-worker-toolwear-code-training-engineer agentteams-worker-toolwear-evaluation-governor agentteams-worker-toolwear-report-memory-curator
```

这些命令只启动明确列出的已有容器，不创建或删除容器。首次部署或镜像重建见 `deploy/agentteams/README.md`。

### 4.2 启动前端和后端

打开 PowerShell 7：

```powershell
Set-Location F:\Toolwear_agent\toolwear_agent_app
& 'F:\Toolwear_agent\baseline\.cache\PowerShell-win-x64\pwsh.exe' `
  -NoProfile `
  -File .\scripts\start_local.ps1 `
  -PythonExe 'F:\uploadtool\anaconda\envs\ToolWear_agent\python.exe'
```

`start_local.ps1` 位于代码仓库的 `scripts` 目录；`baseline` 中只有便携 PowerShell 7 程序。脚本会：

1. 检查 `18100` 和 `18101` 端口。
2. 只在服务未运行时启动 FastAPI 与 Streamlit。
3. 把服务日志写入 `D:\AI_infra\logs\services`。
4. 等待 API、页面、AgentTeams 和 Higress 健康检查。

看到下面地址后即可使用：

```text
前端：http://127.0.0.1:18101/
API：http://127.0.0.1:18100/api/v1/health
Element：http://127.0.0.1:18088/
```

## 5. 前端完整操作流程

### 5.1 新建实验

1. 左侧点击“新建”。
2. 数据集选 `PHM 2010`，刀具选 `C1`。
3. 任务选“四阶段磨损分类”。
4. VB 聚合选 `max`，阈值保持 `90/130/160 um`。
5. 选择需要的信号通道。
6. 默认窗口 4096、重叠率 0.50、小样本比例 0.20、每个 cut 最多 32 个窗口。
7. 输入研究目标后创建实验。

创建后会得到不可变 revision。后续参数变化会形成新 revision，而不是覆盖原实验事实。

### 5.2 数据准备

进入“数据准备”，依次完成：

1. 数据登记与体检。
2. VB 四阶段标签生成。
3. cut 级 train/validation/test 切分。
4. 泄漏审计和小样本分层抽取。

必须看到泄漏审计通过。同一 cut 的窗口不能同时出现在不同数据集合中。

### 5.3 生成候选

进入“候选与参数”，点击调用 LLM。`AlgorithmArchitectAgent` 会结合研究目标、硬件、数据规模和 Registry 生成 2-3 个可执行候选，并展示：

- 模块链和 Pipeline ID；
- 推荐理由；
- 风险；
- 预计成本；
- 当前 P0 是否可训练。

LLM 不能创造 Registry 外的训练入口。响应不合法时会被 Schema/策略拒绝并保留失败 Trace。

### 5.4 审批与训练

1. 人工选择一个候选。
2. 点击批准，生成不可变方案 revision。
3. 执行 Pipeline 校验。
4. 点击“小样本训练”。

训练代码、配置、日志、模型和指标都会保存；不会只在页面显示一个结果。RandomForest/ExtraTrees 可用 CPU，1D-CNN 使用 CUDA。

### 5.5 评估与决策

在“评估与决策”查看：

- Macro-F1 与 Balanced Accuracy；
- 各阶段 precision/recall/F1；
- 混淆矩阵；
- validation-only t-SNE；
- CNN 的 loss 曲线（选择 CNN 时）；
- `EvaluationGovernorAgent` 的问题诊断和下一步建议。

诊断完成后由用户选择继续训练、调整参数、切换方案或停止。多轮无明显收益时应停止或换方案，系统不会无限自动重试。final test 在候选与超参数锁定前保持隔离。

### 5.6 报告与证据

“日志与证据”展示状态时间线、配置、运行日志、图表、报告和 SHA-256；“Agent 协作”展示六 Agent 的调用状态、模型、耗时、Token 和 Trace Evidence ID。

## 6. 六个 Agent 的职责

| Agent | 职责 | 不允许做什么 |
| --- | --- | --- |
| ExperimentManagerAgent | 拆解任务、协调状态和人工审批 | 绕过审批或直接训练 |
| DataStewardAgent | 数据体检、标签、切分和泄漏解释 | 修改原始数据 |
| AlgorithmArchitectAgent | 生成 Registry 兼容候选 | 生成任意可执行命令 |
| CodeTrainingEngineerAgent | 校验方案、训练并保存快照 | 训练未批准方案 |
| EvaluationGovernorAgent | 根据 train/validation 诊断 | 使用 final test 调参 |
| ReportMemoryCuratorAgent | 生成报告和经验记忆 | 编造不存在的 Evidence |

## 7. Element 怎么进入和使用

1. 确认 AgentTeams/Matrix/Element 容器已启动。
2. 浏览器打开 `http://127.0.0.1:18088/`。
3. Homeserver 使用页面默认的本机地址；用 AgentTeams 初始化时创建的本地账号登录。
4. 登录后选择 `Team: ToolWear_agent` 或 `Leader DM: toolwear-experiment-manager`。
5. Team 房间用于观察协作，Leader DM 可向实验管理 Agent 发起任务或询问状态。

Matrix 登录凭据不写入 Git，也不在本说明中明文保存。Element 左侧出现的 `opspilot-zero-demo`、`alert-intake` 等名称属于 baseline 示例，不是刃知的 Agent；演示时只展示 `toolwear-*` 和 `Team: ToolWear_agent`。

## 8. SQLite 的作用

默认数据库：

```text
D:\AI_infra\state\toolwear.db
```

它保存：实验定义、revision、状态转换、人工审批、训练 Run、Agent 调用、Evidence 元数据和可检索经验索引。因此它提供“恢复”和“记忆”能力：重启页面后实验仍在，后续 Agent 也可以检索已经归档的经验。

它不保存：原始 CSV、大型模型文件、图像二进制或 API Key。这些分别存放在受控文件目录或 `.env` 中。

## 9. 怎样验证系统

```powershell
F:\uploadtool\anaconda\envs\ToolWear_agent\python.exe -m pytest -q
F:\uploadtool\anaconda\envs\ToolWear_agent\python.exe .\scripts\verify_golden_flow.py
F:\uploadtool\anaconda\envs\ToolWear_agent\python.exe .\scripts\verify_agentteams_deployment.py
```

`verify_golden_flow.py` 不会重复训练或再次消费 LLM 额度，只读取当前实验事实并复算 Evidence 哈希。`verify_agentteams_deployment.py` 对 Docker、Matrix 和 Skill 证据执行只读核验。
